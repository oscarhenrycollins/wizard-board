# WizardOS Tracker

Display name "WizardOS Tracker". 0.12 (store listing): the app id follows the name, `wizard-os-tracker`, with `renamed_from: [board]`, so `wam app-rename board` moves an installed `board` (data, sign-ins, port, settings) to the new id; the repo was `oscarhenrycollins/wizardos-tracker` (0.16.1: moved to `humanitylabs-org/wizardos-tracker`). 0.13.7: the product is spelled WizardOS (one word), so the id became `wizardos-tracker` and the name `WizardOS Tracker`, with `renamed_from: [board, wizard-os-tracker]` (`wam app-rename wizard-os-tracker wizardos-tracker` moves an installed copy; agent tools are now `mcp__wizard__wizardos_tracker__*`).

Humans manage the work; agents write the PRs. Board shows two kinds of GitHub issue across one organisation (default `humanitylabs-org`):

- **Goal** (label `goal`): a big outcome with a short done-list (a markdown task list). Only humans open and close goals.
- **Bug** (label `bug`): small and specific. Anyone on the team or their agent may report one; it is ready to work as soon as it is filed.

Each person on the WizardOS team (active members of `humanitylabs-org`) connects their own GitHub account with a personal access token; anyone can install it, only team members can use it (0.12). The token is kept on the box only (file mode 0600), validated with `GET /user`, never returned to the view or MCP. Board sees exactly what that token can see. GitHub is the only backend: the app keeps no copy of issues, only a 60-second read cache.

Try it (0.14.0, Miguel): the **Try it** switch on a Human review row is the change's real **feature switch on the Wizard you are looking from** — the same state as Settings › Appearance › Try new features (one shared state, `Pages/wizard-look/look.json` `tweaks`). Messages: on For everyone (`locked`, or a 409) "Switch to For testers in Settings to try this"; the switch is not in this box's catalog, or the box's App Manager has no route yet (404) "Update to try this"; opened outside a Wizard (no JSON answer) "Open the Tracker inside your Wizard to try this."; no switch named "This change has nothing to switch on.".
**`Switch:` convention (builder hand-over):** the builder's "What to check" comment (the one that hands the item to AI review / Human review) ends with one line `Switch: <author>/<id>` naming the shell tweak id the change sits behind (e.g. `Switch: miguel/send-and-go`; the id in wizard-ux `wizard-os-home/tweaks/catalog.json`). The newest builder comment with such a line wins; a `Switch:` line in the issue body is the fallback; no line = nothing to switch. The server parses it (`switch_of()`, `SWITCH_LINE`) and serves it as `switch` on Human/AI review cards; Markdown emphasis or backticks around it are fine.
